# Honest acceptance/demo flow

A valid real acceptance requires: upload actual product/brand inputs; configure real notebook models and sponsor keys; start a bounded run; obtain at least two actual generated candidates; retain immutable references; execute genuine compatible evaluators; obtain a live TypeSafe decision; generate a new video/image using its actual parent plus original references; compare preserved branches; observe verified root/child Weave delivery; inspect actual cortical data; record human feedback; explicitly approve an eligible PAUSED Meta deployment; read back real IDs and available reports; export real evidence for research.

Keep checkpoint versions, prompts, model parameters, seed when available, GPU/runtime/cost measurements, artifact hashes, run IDs and provider receipts. A test fixture, 200 response, attractive UI, configured registration or uncolored brain mesh does not satisfy the live model acceptance gate.

Without credentials/models, show the truthful waiting/unconfigured state. Do not populate a fake campaign to make the demo look finished. Optional unavailable stages remain explicitly marked. The real model acceptance checklist is not complete merely because all CPU tests pass.
